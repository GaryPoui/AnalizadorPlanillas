PROCESO REALIZADO — 2026-08-18
------------------------------------------------------------

1. SISTEMA HIBRIDO: DISEÑO E IMPLEMENTACION
   Se diseñó e implementó un sistema híbrido de extracción que combina:
   a) Extractor heurístico existente (regex + pdfplumber + tablas) como base.
   b) Claude Haiku como segunda capa: procesa el texto raw (por página en PDFs,
      por chunks en XLS) y extrae productos que el heurístico omite.
   c) Merge inteligente: el heurístico es la base; Claude agrega códigos nuevos
      y enriquece descripciones cuando la suya es más larga.

   Scripts creados:
   - tmp/tmp_test_lct_claude.py       → híbrido para PDFs (generalizable)
   - tmp/tmp_test_n95_claude.py       → híbrido para N°95 (misma lógica)
   - tmp/tmp_test_microcontrol_claude.py → híbrido para XLS

2. BUG IDENTIFICADO Y CORREGIDO EN EJECUCION
   Durante la primera corrida del híbrido LCT, páginas 12-14 devolvían
   0 filas con exactamente 2,000 tokens output. Diagnóstico: max_tokens=2000
   truncaba la respuesta JSON a mitad. Fix aplicado:
   - max_tokens subido de 2,000 a 6,000.
   - Agregado salvamento de JSON truncado: busca el último "}" válido
     y cierra el array → recupera objetos completos del response cortado.

3. BATCH TEST — AR36 EXCLUIDO
   Se modificó tests/batch_test_listas.py para excluir LISTA AR36 del
   batch automático (variable SKIP_FILES, default="LISTA AR36").
   AR36 es PDF escaneado que requiere OCR+Claude y cuesta ~$0.24 por corrida.
